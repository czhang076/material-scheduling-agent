# 验收与证据计划（尚未执行）

## 1. 评估分层

|层次|能够证明什么|不能证明什么|
|---|---|---|
|业务单元测试|规则、区间、状态迁移、指纹的确定性约束|真实模型会选对动作|
|SQLite 集成测试|持久化、幂等、版本、事务、并发行为|真实平台发布/锁定|
|HTTP 协议模拟|模型请求结构、工具调用解析、异常处理|真实服务兼容性或决策效果|
|离线 Mock 验收|同一执行器中的完整流程与保护措施|真实模型 ReAct 达标|
|真实模型验收|当前模型/提示/工具下的实际行为|未经评测输入上的普遍可靠性|

M1 已执行基础规则与本地资料集成测试，见 [M1 验收](../M1-ACCEPTANCE.md)。本页 A/W 的完整 Agent/网页验收场景尚未运行；不能把 70 个基础方法换算为这些场景通过。

|A18|相接时段、跨偏移等价时间|相接可用；等价时刻冲突|区间和归一化测试|
|A19|规则/素材变化后重复请求|旧版失效；同 ID 新版本或阻断|旧同意不继承|
|A20|更换占用时段后重复请求|重新核验，建议跟随当前情况|两次数据快照和 Trace|
|A21|一批中部分缺失或失败|保留成功项，返回 PARTIAL|逐项状态和真实草稿|
|A22|同批两个待确认项选相同时间|第二项重新选时段或未完成|同批建议不冲突|

## 4. 真实模型验证计划

待用户配置后，先执行正常、冲突、资料不足、阻断风险和保存失败路径；对关键路径重复 3 次，记录实际模型名、输入、规则版本、代码版本及随机性设置（服务支持时）。

改变占用时段或规则内容后再运行，对照工具观察和下一动作。保留失败运行，不能只挑成功样本。

如果成本有限，先完成两条真实动态路径，并在评估中明确样本数与未覆盖项。不能把离线测试数量转成真实模型准确率。

## 5. 指标定义

|指标|单位与分母|判定来源|
|---|---|---|
|验收通过率|通过的已执行场景数 / 已执行场景数，按层分别统计|逐用例实际断言|
|越权次数|次；所有已执行保存/确认尝试|保护日志及持久化事实|
|重复新增草稿数|同请求项第二次执行后的净新增份数|真实数据库计数|
|草稿冲突数|个；最终 READY 草稿的同渠道重叠对|区间复核|
|保存状态误报数|次；已执行保存尝试|输出与数据库/事务结果对照|
|硬性时间未经确认变更数|次；涉及硬性时间变化的已执行案例|原要求、候选、确认记录|
|动态决策合理率|合理的已评审转移 / 已评审转移，真实与 Mock 分开|前一观察与后一动作|
|工具/模型消耗|每次运行的次数与耗时；真实时可加实际 tokens|Trace 与服务 usage|

不设无依据的“模型准确率达到 95%”目标。关键缺陷目标为零；一旦发生必须记录并修复后复跑，不能只提高总体通过率掩盖。

## 6. 证据包

每个已执行案例计划包含：输入 JSON、合成数据快照引用、实际输出 JSON、实际 Trace JSONL、运行清单、执行命令和对应断言结果。

离线与真实材料分模式标记；运行清单记录代码 commit 和文件校验值。`docs/03-evaluation.md` 应引用具体文件，不能只有截图或口头结论。

## 7. 进入交付的标准

- 六项必验均有可复现实际证据。
- 权限、幂等、保存误报和 READY 冲突测试无未解决关键缺陷。
- 真实模型至少两条动态路径；若尚无则明确“ReAct 效果待验证，未完整满足考核”。
- 干净环境能按 README 安装运行。
- 网页完成后有实际交互验证；关键状态与 CLI 一致，不通过前端绕过确认和保存保护。
- 五份文档准确反映已实现、未实现和验证边界，附最终 GitHub URL 与 commit SHA。
