# 用户流程与场景推演（设计稿）

以下是预期业务过程，不是实际执行记录。用户已选择先 CLI 后轻量本地网页，两种入口共享相同业务语义。

## 1. 用户任务

内容运营提交待处理素材和排期要求，查看每项审核结论、风险原因、时段建议与草稿保存结果。用户只对明确展示的方案版本作出同意；任何入口都不能触发真实发布。

一次结果应让用户回答：哪些已形成可用草稿、哪些等我确认、哪些缺资料、哪些被阻断、哪些操作失败，以及下一步该做什么。

## 2. 正常排期

输入：M01 资料齐全、规则通过，要求 18:00，占用长度 30 分钟，该渠道 18:00–18:30 空闲。

预期：模型选择读取、审核与查询；看到空闲后选择保存。保存事务复核，形成 READY 草稿并占用本地容量。结果保留审核证据、18:00 原要求和草稿身份，不称已发布。

对应计划：A01。

## 3. 冲突、建议与确认

输入：M01 硬性要求 18:00，18:00 被占，19:00 在搜索范围内且空闲。

|阶段|系统预期行为|用户可见事实|
|---|---|---|
|查询目标|工具返回冲突，模型观察后选择替代查询|18:00 仍是原要求|
|查询替代|工具返回 19:00，模型选择保存建议|候选是 19:00，须同意时间变化|
|保存建议|保存同一项的 PENDING_CONFIRMATION 草稿|已保存建议，不是已确认或已发布|
|用户同意|提交当前草稿版本与 TIME_CHANGE 事项|本次同意针对明确版本|
|确认复核|再次查资料、规则及占用|通过才转 READY，否则说明新冲突|

若用户未确认，系统停在待确认，不擅自占用或把 19:00 标成已确定发布时间。用户拒绝时也不推断允许另选时间；修改原始要求需要明确新请求。

对应计划：A06、A14、A15、A17。

## 4. 缺资料与补齐

输入：M02 缺版权状态。

- 有带来源的补充资料：模型选择补查，工具只填缺失字段，随后重新审核。
- 无补充资料：返回 NEEDS_INPUT，具体指出缺版权状态；不猜测、不生成可用草稿。
- 用户后来补齐：显式更新资料，再以同请求 ID 重跑；原始时间要求没有改变，不新增第二份对应草稿。
- 补充资料与现有事实矛盾：列出冲突，交给用户核对，不能默默覆盖。

对应计划：A02、A03、A19。

## 5. 风险分级

明确版权争议属于 BLOCKED：列出规则与证据，无确认放行入口。

需要人工核对的风险属于 NEEDS_REVIEW：可保存待确认草稿，用户看到具体风险事项后决定是否接受。接受之后可以形成 READY 草稿，但审核结果和风险仍保留，不修改成“无风险”。

若缺资料与风险同时存在，完整展示全部发现；不能只展示总体状态而隐藏更严重问题。

对应计划：A04、A05、A24。

## 6. 重复请求与当前事实变化

|输入变化|预期|
|---|---|
|相同请求、资料与占用未变化|返回同一草稿，不新增；合法复用不增加版本|
|相同请求、其他时段占用变化|复核当前候选；不因无关变化重建草稿|
|相同请求、当前候选新增占用|旧方案过期，重新查询或返回无法满足|
|相同请求、素材或规则改变|重新审核，旧确认失效；更新沿用草稿 ID|
|相同请求 ID，但改了原始发布时间|拒绝身份冲突，原数据不覆盖|

对应计划：A08、A09、A19、A20。

## 7. 批量、失败与恢复

输入：M01 合法、M02 缺资料、M03 的保存操作失败。

预期逐项交付：M01 的 READY 草稿保留；M02 列缺口；M03 明确本次保存 FAILED 或 UNKNOWN。整体为 PARTIAL，不能回滚 M01 的合法结果，也不能声称全部完成。

恢复时复用原请求 ID。读取已有合法草稿并复核，只对仍未完成或已经过期的项重新处理。UNKNOWN 先核验存储，不换请求 ID 盲目再建。

对应计划：A10、A11、A12、A21。

## 8. 交互验收

未来无论网页还是报告，都必须清楚表达：

- 原始要求与建议值并列，时间带时区。
- 风险与资料缺口可定位到来源和规则。
- 待确认事项明确，操作绑定版本，不使用无上下文的“全部同意”。
- 保存失败、旧草稿仍存在、结果未知三个事实分开呈现。
- 可追溯到实际 Trace；设计说明不能冒充运行记录。
