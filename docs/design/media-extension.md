# 图片与视频扩展设计边界

状态：用户选择预留扩展设计，首版不实现视觉模型或媒体处理。

## 1. 当前行为

审核覆盖范围只有元数据和文案。首版不接受图片/视频文件或 URL 作为待审核输入，不自动下载素材，也不调用视觉模型。

结果应明确图片/视频未检查。不能由文件名、素材描述或文案通过推导画面安全。

## 2. 未来扩展所需契约

先新增有版本的媒体输入契约，再增加真实检查实现；当前 v1 严格输入不会因“预留扩展”而默许任意附件字段。

未来可能包含：媒体身份与内容指纹、受控位置、MIME、大小、时长、实际检查的页/帧/时间段，以及检查器和模型版本。

证据统一表达来源、版本、检查范围和定位方式；文本使用字段和码点区间，图片使用图像身份及区域，视频使用内容身份、时间段和帧引用。不同定位不能混用。

## 3. 工具与状态扩展

未来检查工具仍返回结构化 findings，交由相同审核聚合和保存保护处理。模型可决定是否调用新增检查工具，但不能直接标记视觉已通过。

检查覆盖不足、工具失败或模型响应无法映射到实际媒体证据时，输出未完成范围；不得降级成只查文案后标整份素材 PASS。

新增视觉结果要进入审核快照。媒体文件或检查范围改变后，旧审核及确认必须失效。

## 4. 图片扩展需验证

文件读取、格式限制、模型实际图像输入、证据位置、缺图、解码失败、超限与提示注入。仅伪造图片描述的 Mock 不能证明模型看过图片。

## 5. 视频扩展需验证

在图片基础上增加受控抽帧、字幕/音轨来源、时间戳映射、覆盖范围与资源预算。抽样检查只能报告实际采样范围，不能宣称所有帧或全部音轨已审核。

不预先创建空视觉适配器、安装媒体依赖或选择视觉模型。实际需要时按上述契约扩展，并单独留真实运行和失败证据。
