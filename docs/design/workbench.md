# 轻量网页工作台设计

状态：D02 已由用户选择，M5 已实现本地网页与 HTTP 服务，实际验收见 [M5-ACCEPTANCE](../M5-ACCEPTANCE.md)。未创建线上站点。

## 1. 目标与范围

让评审和内容运营看清素材为何需要处理、系统如何调整动作、哪些草稿可用、哪些还需用户确认。网页复用同一应用用例和数据库，不另写审核或排期规则。

首版为本地单用户工作台，仅监听回环地址；不提供账号、团队协作或线上部署。实现选择 Python 标准库服务及原生 HTML/CSS/JavaScript，无前端框架或第三方运行依赖。

CLI 是完整验收入口。网页只是另一种展示和可信用户操作入口，真实模型密钥始终留在服务端本地配置。

## 2. 页面结构

采用一个工作台主页面，包含任务、草稿和执行记录三个视图，避免拆成复杂管理系统。

|区域|内容与动作|
|---|---|
|顶部运行信息|Mock/真实模式、运行状态、规则/数据版本；仅在实际使用真实模型时显示对应模型|
|任务输入|粘贴或选择请求 JSON、格式预览、运行；不接受图片/视频上传|
|素材列表|逐项审核、时段、草稿和保存状态，支持按待确认/缺失/失败筛选|
|详情区域|原始要求与候选并列，风险原文、来源、缺口和待确认事项|
|草稿视图|草稿 ID、版本、最新核验时间、可用/待确认/过期状态|
|执行记录|按实际顺序展示模型动作、参数摘要、工具结果、错误与公开理由|

状态使用文字和图标，不只靠颜色。时间明确显示日期与 UTC 偏移；详情始终可回到实际素材版本和 Trace。

## 3. 确认交互

仅当前待确认草稿显示确认入口。确认面板并列展示：

- 原始硬性时间与候选区间。
- 本次变化、风险原文和每项待确认 ID。
- 草稿 ID、版本以及“确认后仍仅为草稿”的说明。

用户逐项接受后才启用提交；禁止无上下文的一键全部放行。前端传预期版本和 confirmation_id，服务端重新核对全部事项、资料和占用。

若当前版本变化或候选被占，保留用户看到的旧值并提示需刷新/重新规划；不能把过期确认自动提交到新版本。页面随后展示最新服务端事实。

## 4. 提交、重试与恢复

- 双击运行按钮：复用同一 request_id；后端不允许相同请求同时产生两个活动运行。
- 双击确认：同一操作复用 confirmation_id；相同 ID 不同内容拒绝。
- 页面刷新或关闭：不表示后端运行已经取消；重新按 run_id 查询实际状态，不自动重新提交。
- 浏览器网络断开：显示“连接中断，结果待查询”，不能显示保存失败或成功。
- 重试业务请求：保留原身份，复核已保存项后处理未完成项。
- 保存 UNKNOWN：先检查当前草稿和审计，不提供“换一个请求再存”的快捷动作。

首版不设计运行取消按钮，避免用前端停止轮询冒充取消实际任务。运行仍受执行器总时限和调用上限约束。

## 5. 拟定本地 HTTP 契约

以下核心路径已实现，所有写操作调用现有应用用例。另提供 bootstrap、提交编号查询、运行列表、Trace 下载和请求只读查询。

|方法与路径|用途|关键语义|
|---|---|---|
|POST `/api/runs`|提交严格请求并启动运行|返回运行 ID；重复活跃请求复用既有运行|
|GET `/api/runs/{id}`|查询状态和逐项结果|明确当前运行是否结束及实际停止原因|
|GET `/api/runs/{id}/events`|读取脱敏事件|分页或游标，按真实序号，不返回模型私有推理|
|GET `/api/drafts/{id}`|读取当前草稿|只读返回版本、最近持久化核验事实及时间；需要新复核时使用 POST|
|POST `/api/drafts/{id}/confirm`|用户确认当前版本|绑定事项/版本/操作身份，原子复核|
|POST `/api/requests/{id}/revalidate`|显式复核当前资料与占用|状态变化记录审计，不启动模型规划|

GET 接口不执行新的确认或保存。外部资料导入等会影响草稿状态的操作在导入事务中触发失效；显式复核使用 POST，避免浏览器预取触发写入。

HTTP 错误不取代业务状态：运行已启动但其中素材被阻断仍是可查询的业务结果。版本冲突返回明确冲突码；不返回 200 加伪造成功。

## 6. 本地运行架构

静态页面和 HTTP 接口由同一本地服务提供。接口直接调用应用用例，不拼接 shell 命令调用 CLI。

首版最多一个活跃 Agent 运行；确认、数据导入和 CLI 访问数据库仍依靠事务保证一致性。重叠运行申请返回忙或复用状态，不无限排队。

前端采用有界轮询，进入终态或离开页面后停止。服务重启时，未完成运行标为中断，草稿事实保留；用户复用请求 ID 发起恢复，不把旧任务当成仍在运行。

活动运行复用规则须在应用层或持久化身份中实现，不能只靠禁用按钮。

## 7. 安全与信息展示

- 本地服务校验 Host/Origin，写操作使用本地会话防伪标记；不开放任意跨域。
- 服务端密钥、原始授权头和未筛选异常不能返回给前端。
- 文案、模型理由、工具摘要按文本渲染，不能把其中 HTML 当作页面执行。
- 模式标签来自运行清单，不由前端猜测；Mock 始终显著标注。
- 保存状态来自服务端，按钮点击或 HTTP 请求发出都不等于保存成功。

本地会话防伪机制不等价于多人认证。若以后部署到可被他人访问的环境，必须另行设计认证、权限与数据隔离。

## 8. 验收

网页要覆盖正常查看、冲突建议、版本确认、双击、断网重连、风险片段、Mock 标记及敏感信息不出现在响应中。计划用例列入 [测试计划](test-plan.md)。

先通过 CLI 六项必验和确认闭环，再进入网页实现；网页完成后做实际交互验证，不以设计截图代替运行结果。
