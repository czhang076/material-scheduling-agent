# 元数据与文案审核设计

状态：D01 已选择，M1 已实现确定性规则与证据，M3 已有离线 Agent/CLI；本页保留审核设计，没有真实模型审核效果结果。

## 1. 当前覆盖范围

审核对象为合成素材的元数据与待发布文案，不读取图片或视频文件。

- 元数据：素材身份、版本、版权状态、支持渠道、必要字段与来源。
- 文案：标题和 `copy_text` 中可按配置检查的禁用承诺、品牌规则和人工审核提示。
- 描述和补充资料：用于上下文与补查，不能作为用户授权，也不能把自述当成版权证明。
- 输出明确 `review_coverage=[metadata, copy_text]`，并说明图片/视频内容未检查。

规则 PASS 只表示通过当前规则集覆盖的检查，不表示真实产品事实、法律合规或整条视频已被全面验证。

## 2. 数据契约补充

素材增加 `copy_text`：待发布正文，非空字符串，首版最多 8000 个 Unicode 码点；title 最多 200 个码点。超出上限显式拒绝该资料导入，不静默截断后声称全文通过。

本项目用于排期的素材需具备 title、rights_status、supported_channels 和 copy_text。缺少正文属于 NEEDS_INPUT。后续如需支持纯画面无文案素材，应另定义明确的“不适用”语义，不能把缺失当成无需审核。

上述“需具备”是审核可通过条件，不是把资料不足素材拒之门外的导入条件。身份/版本/来源和已有字段类型合法的素材可以缺少审核资料并进入补查流程。版权 unknown 也属于待补充，不能当作已获得授权。

版权枚举、渠道枚举由版本化规则集明确；不从描述里猜测“应该有版权”。补查只补缺失字段，保留来源和版本。

## 3. 规则与结论

|规则类型|检查方式|结论与解释|
|---|---|---|
|必填字段|严格检查存在、类型与非空|缺失 NEEDS_INPUT，指出具体字段|
|版权禁止状态|规则配置枚举匹配|BLOCKED，保留字段证据|
|渠道不支持|素材支持范围与请求渠道比较|BLOCKED，不能偷偷换渠道|
|明确禁用文案|按规则配置在 title/copy_text 精确匹配|BLOCKED，返回命中原文及规则|
|需人工确认标签/措辞|配置条件匹配|NEEDS_REVIEW，形成具体待确认事项|

禁用文案是本项目合成品牌规则，不冒充任何平台的官方政策。规则文件不允许执行任意表达式或代码。

模型负责在工具观察之后决定补查、继续、请求确认或停止；模型给出“我认为无风险”不能撤销规则 findings。规则之外的疑点可以作为公开说明记录，但不能被描述成已验证事实。

首版不宣称理解所有否定、引用、讽刺或上下文。针对这类边界保留样例，明确规则的预期和局限；不能为了消除某个误报而让模型绕过硬阻断。

## 4. 证据定位

每个 finding 计划包含：

- `rule_id`、规则集版本、严重程度、明确原因。
- `source_id`、material_id、素材 revision、内容指纹。
- 字段路径，例如 `copy_text` 或 `rights_status`。
- 原字段值或命中片段；文本命中包含 `start`、`end`，采用原始字符串的 Unicode 码点半开区间。

前端 JavaScript 的 UTF-16 下标与 Unicode 码点不同。网页按码点转换高亮或直接展示服务端返回的分段，不能拿 Python 下标直接调用浏览器 substring；必须覆盖中文、emoji 和换行样例。

任何查找归一化只能用于检测；返回片段必须能映射回原文。映射失败时不得伪造位置或引用，返回检查失败/待核对。

## 5. 版本与确认

copy_text 及标题变化都改变审核快照。保存或确认前再次检查指纹；旧版本通过或旧用户同意不能应用到改写后的文案。

人工接受 NEEDS_REVIEW 只记录接受的风险事项，不把审核结论改为 PASS。BLOCKED 或 NEEDS_INPUT 没有“我同意所以放行”的入口。

## 6. 失败与输出

规则工具异常或证据无法定位时，审核状态保持未完成，禁止生成 READY 草稿。保留已成功读取的事实，并明确尚未完成哪些检查。

最终结果与网页同时展示覆盖范围、规则版本、所有 findings、待补充项和人工接受记录。不能只用绿色“通过”掩盖检查范围有限。

## 7. 后续验证

在现有用例之外增加文案缺失、命中片段定位、emoji 下标、变更后旧确认失效、超长拒绝、未经读取的视觉内容不误报已审核等场景。见 [测试计划](test-plan.md)。
